## Findings and corrections

1. **Pinned source but mutable release asset (correctness/security).**
   The Rust workflow verified the tarball's embedded source commit but not
   its actual contents. Its release publisher also used
   `gh release upload --clobber` under an existing versioned tag.
   The Rust workflow now checks the exact release-asset SHA-256 **before
   extracting it**, and fails if the checked-out EDG source commit differs.
   The upstream promotion workflow refuses to overwrite an existing asset
   and compares the expected digest if the release already exists.
   Fixes: Rust `5eba4d6`, `3b2a1ee`; EDG `7f91818`.

2. **Cache not isolated by native ABI revision (correctness).**
   Restore-key prefixes previously allowed Cargo targets compiled against
   an older EDG IL layout to be restored after updating upstream EDG.
   Cache keys and restore prefixes now contain the EDG source commit and
   an explicit pinned Rust toolchain version. A changed revision requires
   a fresh native bridge build. The build script observes
   `EDGCPP_EDG_REVISION` in CI; local builds without this variable track
   EDG source/header inputs, the compilation database and the archive.
   Fixes: Rust `668c08c`, `47c473c`, `13cd82e`.

3. **Redundant upstream native compilation (CPU).** Adding the original
   promotion workflow caused both a promotion run *and* the regular
   EDG native release build on the same upstream branch push.
   The regular release workflow now ignores GitHub workflow-only and
   Markdown-only branch changes. The one-time promotion workflow is
   manual-only, avoiding another automatic run.
   Fixes: EDG `23ca69d`, `7f91818`.

4. **Excessive successful CI logging (resource use).** The integration
   fixture printed the complete IL result even when successful.
   Assertions now use quiet grep; the last 100 IL lines are shown
   on a failing assertion, preserving actionable diagnostics.
   Fix: Rust `5eba4d6`.

5. **Documentation alignment.** Updated CI documentation with pinned asset
   digest, source-revision validation, cache scoping, generated-header
   build, and non-overwriting publication. The README no longer claims
   the workflow performs configuration only.
   Fixes: Rust `535d55f`, `d67972c`.

## Verification and limits

The successful Rust CI run
https://github.com/bingundu/edgcpp-rust/actions/runs/39490676747
verified the checksum-enabled release download, Rust tests, Clippy and
the integration fixture. The original prebuilt EDG archive comes from
https://github.com/bingundu/edgcpp/actions/runs/39259142410.

The newer cache-version and build-script changes require a separate
green run; refer to the workflow history for their latest status:
https://github.com/bingundu/edgcpp-rust/actions/workflows/build.yml

The upstream promotion workflow's new idempotency behavior was
code-reviewed but not re-executed; the pinned asset already exists.
Upstream tagged release builds still compile EDG once intentionally.

This review does not claim that a cached build from an earlier revision
is binary compatible with a different EDG IL configuration. Pin new releases
and update the source revision, checksum and build configuration together.
